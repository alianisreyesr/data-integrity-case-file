## What this is

A workspace that models how a quality / compliance professional structures a **data integrity investigation**:

1. **Intake** — describe the signal (audit finding, complaint, system anomaly)  
2. **ALCOA+ gap analysis** — which integrity attributes may be affected  
3. **Evidence log** — what was reviewed (synthetic)  
4. **Root cause & CAPA sketch** — corrective / preventive actions (illustrative)  
5. **Case status** — open → investigating → pending QA → closed  

Designed to practice the **vocabulary of FDA / MHRA / PIC/S data integrity** expectations without touching real GxP data.

**Stack (planned):** Python · FastAPI · SQLite · React · Docker · CI
