# Educational investigation playbook

Synthetic walkthrough only. Not an SOP for a real quality unit.

## 1. Intake
Open a case with the signal type (audit finding, access anomaly, metadata mismatch). Record the system and the person opening the file.

## 2. ALCOA+ scan
For each relevant attribute, decide whether the record is attributable, legible, contemporaneous, original, accurate, complete, consistent, enduring, and available. Log gaps with a rationale.

## 3. Evidence
Attach audit-trail review notes, access-log excerpts, and interview notes — all fictional in this repo. Prefer primary system evidence over recollection.

## 4. Optional AI triage
Request local-model suggestions. **Accept, reject, or modify each item.** The model never writes gaps by itself.

## 5. CAPA
Turn confirmed gaps into corrective and preventive actions with an owner and a check for effectiveness.

## 6. QA closure
Close only when gaps, evidence, and CAPA are consistent. The application audit log should show who did what, in UTC.

If this were a real investigation, organizational procedures, validated tools, and qualified reviewers would apply. This prototype only shows the information architecture.
